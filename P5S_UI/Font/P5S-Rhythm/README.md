# P5S Rhythm Bold — 标准 / 紧凑版 1.000

标准版：`../P5S-Rhythm-Bold.ttf`；内部字体族：`P5S Rhythm`。紧凑版：`../P5S-Rhythm-Compact-Bold.ttf`；内部字体族：`P5S Rhythm Compact`。两版字重/样式均为 `Bold`（700），保留 Fredoka Bold 的原始粗度。

## 设计

基于用户提供的 Fredoka Bold 2.001，保留圆润、厚实的笔形；A–Z、a–z、0–9 共 62 个字符沿用 P5S Showtime/Bounce 的逐字光学倾斜表。正角度表示顶部向右，负角度表示顶部向左。这些角度是依据参考外观整理的设计参数，不是参考字体中存储的精确角度。

直接旋转直立的原始轮廓，保持每字原来的最低点；标准版每侧留白 24–48/1000 em，数字为比例字宽。构建只读取 Fredoka 和角度表，不读取、复制或合并微软雅黑字形，也不加入中文。

先展开全部组合字再调整目标字，避免重音字意外跟随变形；其余 265 字形的轮廓与基础字宽保持。保留原有 320 字符映射，其中非 ASCII 字符没有套用这次倾斜设计。

与重新设计的 ASCII 字形相关的旧直立字偶距清除，使用标准侧留白排版；其余原始字偶距、脚本与语言入口保留。12 条涉及目标字母的常规/可选拉丁连字规则停用，避免 `fi`、`fl`、`ffi` 等重新合成旧直立轮廓。原有分数、上标、序数及其他非目标功能保留，主动启用这些功能时使用原字体对应的特殊字形。

133 个目标基字的组合重音锚点随轮廓变换；标记字形本身保持原样。原作者的完整多语言排版不作为本次游戏用途的验证承诺。旧 hinting 及来源静态轴元数据清理；内部名称独立命名，保留原有 Bold 身份和原作者信息。

## 紧凑版

采用 Showtime/Bounce 当前紧凑方案：62 个 ASCII 英文字母和数字每侧留白 6/1000 em，逐对目标轮廓空隙 6 单位，纵向余量 3 单位，单对最大收紧 180 单位。字形仅水平平移，形状、粗度、倾斜与纵向坐标完全保留；标准版文件不改写。

3844 对组合同时写入 GPOS 与传统 kern。GPOS 为拉丁文和纯数字使用的 DFLT 入口提供新字距；原有非目标字偶距、希伯来文、标记及连字功能保留。133 个目标基字的重音锚点随水平平移同步调整。原有非目标字符字宽不变，没有新增中文。

HarfBuzz 实际排版下，数字行 `0123456789` 比标准版短 10.83%，大写 A–Z 行短 12.00%，小写 a–z 行短 13.56%；`HP` 短 11.59%，`SP` 短 9.41%。这些是指定样本结果，实际文字比例依字符组合而变；客户端忽略字偶距时仍使用收紧后的基础字宽。

两版共用下方来源声明与 OFL.txt；紧凑版修改信息也写入字体内部 name ID 10。

## 复现与验证

依赖 Python、fonttools。在本目录运行 `python build.py`，输入为原始 Fredoka TTF 和 `tilt-map.json`。源文件摘要固定校验，字体时间戳固定，构建结果记录在 `build-report.json`。

紧凑版另需 Pillow、numpy，运行 `python build_compact.py`。输入为标准版 TTF，固定校验标准版摘要；独立输出 Compact 字体，参数与样本文字宽度写入 `compact-build-report.json`。

已验证：所有字体表解析、265 个非目标字形展开轮廓/基础字宽一致、320 字符六种字号渲染、Windows 临时私有加载/卸载、重复构建一致；两个拉丁字偶距查找共 213858 次组合核对；3844 对 ASCII 组合在 HarfBuzz 默认排版中保持逐字倾斜、最小边界间隙 48/1000 em。希伯来文、预组重音字和标点样本文字排版保持；常规/可选连字行为符合本次设计。

紧凑版已验证：327 字形轮廓仅水平平移、265 个非目标字形基础字宽保持；320 字符六种字号渲染、Windows 临时加载/卸载、重复构建一致通过。3844 对组合的 GPOS 与传统 kern 独立排版一致，禁用字偶距回退正常；非目标 GPOS 与希伯来文/预组重音字/标点样本保留。独立 2000 ppem 栅格测量最小间隙 4/1000 em，不能据此保证小字号描边不相接。

两版字体尚未加入 `/p5s` 静态清单，原有 Lua、TOC、默认字体、保存设置和其他字体均未修改。正式服加载、HP/SP 和数字显示、字偶距支持、小字号描边、重启/切换表现仍需接入后验证。
